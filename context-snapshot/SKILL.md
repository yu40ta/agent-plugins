# Skill: Context Snapshot

`/compact` や `/clear`・新セッション開始で会話文脈が失われても、作業の「現在地・直近判断・次アクション」を手元のスナップショットから復元できるようにする軽量 skill。**mid-session の compact 生存**に特化する (完全な引き継ぎが必要な場合は、そのための別の引き継ぎ生成手順を使う)。

---

## 背景と設計方針

外部プラグイン `compact-plus` は同じ目的 (作業文脈の維持) を掲げるが監査で Fail した。`PreCompact` の度に無承認の特権サブプロセスを勝手に起動し、transcript を外部送信し、LLM 要約を無検証で context へ再注入する (注入面のリスク) ためである。本 skill はその**目的だけ**を、危険面を全排除して満たす。以下を**絶対にしない**:

- **(a) 自動 `PreCompact` hook にしない** — 手動起動のみ。自動再注入を避けることが本 skill の存在意義。
- **(b) 外部送信しない** — transcript の複製も外部送信も行わず、ローカルの決められた出力先にのみ保存する (下記「出力先」参照)。
- **(c) 復元時に本文を事実として扱わない** — restore はスナップショットを読んで要点を提示するだけで、記載内容は git/gh の実状態で裏取りしてから信じる。**なお `@path` で渡された場合はハーネスが本文を context へ展開するため「注入しない」ことは技術的に不可能**。本 skill が担保するのは「注入されないこと」ではなく「**注入された本文を無検証で信じないこと**」である。

---

## 起動条件

- **手動起動のみ**: `/context-snapshot [save|restore]` (引数なし = `save` 既定)。
- **自動発火機構は持たない**。自動再注入を避けるのが存在意義のため、`PreCompact` 等の hook・settings は**作らない**。自動起動が不適切な skill は「手動実行を推奨」と明記する運用に従い、本 skill は対応 hook/settings を持たないことを明示する。したがって発火機構の実装は不要 (この明示自体が整合担保)。

---

## 使いどころ

- **save**: `/compact`・`/clear` を打つ**直前**に退避する。長考ループや context 肥大の兆候が出たときも同様。
- **restore**: `/compact` 直後・`/clear` 後・新セッション開始時に、直近のスナップショットを読み込んで現在地を復元する。

---

## save: 自己完結の要件 (最重要)

**ユーザーは復元時に `/context-snapshot restore <path>` だけを入力する。** それ以外の情報を口頭で補わない前提で書く。したがって save の合格条件は「**このファイル 1 つで復元セッションが次の一手を打てる**」ことであり、単なる項目の埋まりではない。

**ただし save は context が尽きかけた時点で打つ。** 重い調査を伴うと save 自体が完走しない。そこで要件を**必須と努力目標に分ける**。

### 必須 (これが欠けたら save は失敗とみなす)

| # | 検査 | 落ちていたらどうするか |
|---|---|---|
| A | **`## 🚀 起動手順` があり、読み取り専用コマンドがコピペ可能な形で書かれている** | 対象 dir への `cd` を含める。git 文脈が無い作業では git コマンドを置かず「git 復元は不要」と書く。**副作用のあるコマンド (commit/push/削除/生成) は置かない** |
| B | **`## ⭐ 直近の重要判断と理由` に、採用した方針と却下案の理由が書かれている** | compact で真っ先に消える情報。ここだけは分量を惜しまない |
| C | **`## 未完ステップと次アクション` の各項目に着手時の判断分岐がある** | 「A を見て無ければ B」「前提が未了なら先にそれを促す」まで書く。1 行メモにしない |
| D | **`**このターンでユーザーに聞くこと**` が明示されている (無いなら「なし」)** | 復元セッションが余計な確認で往復しないため |
| E | **プレースホルダ `<...>` が残っていない・禁止語で終わる記述がない** | 下記の grep 1 本で機械検出する |

### 努力目標 (コストが 1 コマンドを超えるなら結論の代わりに調べ方を書く)

| # | 検査 | 落ちていたらどうするか |
|---|---|---|
| F | **`## 未解決の問い` の全項目が「save 時点の結論」か「誰に何を聞けば分かるか」のどちらかを持つ** | **他節で結論が出た項目が未解決欄に残っていないか節間で突合する** (残骸が残ると復元セッションがどちらを信じるか判断できない)。1 コマンドで確認できることは確認して結論を書き、それを超える突合は「何をどう確認すれば分かるか」を書いて次へ渡す |
| G | **必読ファイルに「役割」と「読む範囲」が書かれている** | 巨大な台帳を全読みさせない。節名・行範囲・抽出コマンドのいずれかで範囲を切る |
| H | **並行セッションが同じ台帳を進めている場合の優先規則がある** | 「台帳を正とする」等を明記する (食い違いで止まらないように) |
| I | **パスが絶対パスで書かれている** | **シンボリックリンク経由や worktree 外にある保存先は特に絶対パス必須** — 相対パスだと cwd によって解決先が変わることがある |
| J | **`## 落とし穴 / 触らないもの` に踏むと事故る制約がある (1 行 × 最大 5 件)** | 未追跡ファイルの所有者・別セッション必須の作業・先行する運用規範など |

### save 完了前の機械チェック (必須 E の実行)

```bash
# プレースホルダ残存 + 丸投げ表現の検出。ヒットしたら直してから完了とする
grep -nE '<[^>]+>|要確認|要突合|突合が必要|未確認|不明|未指定|TBD' <snapshot のパス>
```

### 収集項目 (テンプレートの見出しと 1:1 対応)

1. `## 🚀 起動手順` (必須 A)
2. `**必読ファイル**` の表 (努力目標 G)
3. `**時限**` の 1 行 (期日・締切。無いなら「なし」)
4. `## 現在地` (1〜2 行)
5. `## ゴール`
6. `## ブランチ / PR / issue` — 絶対パス・記録時の `origin/main` SHA を含める
7. `## ⭐ 直近の重要判断と理由` (必須 B)
8. `## 未完ステップと次アクション` (必須 C)
9. `## 落とし穴 / 触らないもの` (努力目標 J)
10. `## キーファイル` (絶対パス)
11. `## 未解決の問い` (努力目標 F)
12. `## ⭐ 復元セッションが自分で判断すること`

> 項目 12 は「完了報告・引き継ぎには再開用指示文をセットで」という運用と整合させる。**ただしユーザーに貼らせる指示文ではなく、復元セッション向けの判断リストとして書く** (ユーザーの入力は `restore <path>` だけで足りるようにする)。

### save 時の提示

**本文は会話に貼らず、ファイルへ直接書く。** 出力後は「パス + 3 行要約 + 必須 A〜E の結果」だけを提示する。save は context が尽きる直前に打つため、200 行級の本文を会話へ流すのは残り context を自分で焼く行為になる (この点が完全引き継ぎ生成手順の「提示して承認を得る」フローとの明確な差)。

## 出力先

プロジェクトが一時出力の置き場を定めている場合はそれに従う。定めが無ければユーザーに保存先を確認する。ファイル名は `context-snapshot-YYYY-MM-DD-<slug>.md` のように日付とトピック slug が分かる形にする。

- `<slug>` はトピックを表す kebab-case 英語 (例: `pr-issue-hook`)。
- 一時退避が目的なので、恒久的なアーカイブ用ディレクトリには置かない (定期的に整理される想定の置き場でよい)。恒久参照したい完全引き継ぎは、別途持っている引き継ぎ生成手順を使う。
- 深いネストの一時ディレクトリは避け、決めた置き場をフラットに使う。
- **同一スレッドを再 save するときは同じ `<slug>` のファイルを上書き更新する** (日付部分も現在日に更新)。スレッドごとに 1 ファイルを保つ — 版を増やすと候補一覧が膨らみ、restore で「どれが最新か」の判断が必要になって自走を妨げる。別スレッドなら別 slug で新規作成する。

---

## restore フロー

**ユーザーの入力は `/context-snapshot restore <path>` だけである前提で動く。** 口頭の補足を期待せず、snapshot 本文と実状態の突合で自走する。

1. **対象ファイルを確定する**
   - **パス指定あり (主経路)**: その指定を尊重する。**同一 slug のより新しい版があるときだけ**「新しい版があります」と確認する。**別 slug の新しい snapshot は通知も確認もしない** (別スレッドなので無関係。保存先には数十件が溜まることがあるため、無関係な新着を毎回提示すると `restore <path>` だけで自走する要件を自ら壊す)
   - **パス未指定**: `ls -t <出力先>/context-snapshot-*.md | head -5` で候補を一覧し、直近が複数スレッド (別 slug) にまたがる場合は mtime 最新を無条件に採らず、どのスレッドを再開するかを確認する
2. **`## 🚀 起動手順` があればそのコマンドを実行する** — snapshot は自己完結を要件に書かれているため、起動手順がそのまま裏取り手順になっている。
   - **無い場合 (旧形式)**: `## ブランチ / PR / issue` に書かれた**絶対パスへ `cd` してから** `git fetch origin --quiet && git status -sb && git worktree list` を実行する。**git 文脈が「なし」の作業 (完結型の作業等) では git を実行せず** §未完ステップへ直行する (cwd 不明のまま git を叩くと無関係なリポの状態を「裏取り済み」と誤認する)
3. **⚠️ スナップショット本文は ground truth ではない**。記載のブランチ・PR・commit・ファイルは、`git status` / `git log` / `gh pr view` / `git worktree list` で**実状態を裏取りしてから信じる** ([../context-pollution-checker/SKILL.md](../context-pollution-checker/SKILL.md) の再発防止手順にある「再開の起点は本文でなく git/gh の ground truth」と同趣旨)。**本文と現物が食い違ったら現物を正とする** (snapshot 側に優先規則が書かれていればそれに従う)。
4. **本文を事実として扱わない**。`@path` で渡された場合はハーネスが本文を context へ展開するため「注入しない」ことは不可能だが、**裏取りが取れた事実だけを前提に着手する**。副作用 (commit・push・破壊的操作) に進む前に、記載どおりの状態か再確認する。
5. **次の一手へ進む** — `## ⭐ 復元セッションが自分で判断すること` があればそれに従う。**無い場合 (旧形式) は `## 未完ステップと次アクション` の先頭項目を着手対象とみなす**。**snapshot に書いてあることを聞き返さない** (自己完結の意味が消える)。ユーザーに聞くのは snapshot にも必読ファイルにも無い値だけ。

## より完全な引き継ぎとの使い分け

本 skill は「同一セッション内の `/compact`・`/clear` 前後を生き延びる」ための必要最小限・自己完結のスナップショットに特化する。出力前にユーザーへ提示することはしない (本文を会話へ貼らずファイルへ直接書き、残り context を焼かない)。

**session 終了・別端末への完全引き継ぎ**は用途が異なる。完全な引き継ぎでは通常、出力前にユーザーへ提示して承認を得る (「読み手は未来の別セッションの自分」という原則のもと、パス・ブランチ・コマンドを具体的に書く)。そうした完全引き継ぎ用の手順を別途持っている場合は、session 終了時や別端末への持ち越しにはそちらを使う。

## アンチパターン

- **`PreCompact` hook 化して自動再注入する** (= compact-plus の Fail 要因。手動起動を崩さない)
- **transcript 全体を複製・外部送信する** (ローカル保存のみ)
- **restore を無検証で信じ、そのまま副作用 (commit/push/破壊操作) に進む** (git/gh で裏取りしてから)
- **秘匿情報 (トークン・認証情報・PII) を書く** (パス参照に留め、中身は転記しない)

### 自己完結を壊すアンチパターン (save 時)

- **「要確認」「突合が必要」で終わらせる** — save 時点で確認できることは確認して結果を書く。復元セッションに調査を丸投げすると、そこで往復が発生して自己完結が崩れる (実例: 「別セッションのタスクと重複しているか要突合」と書いたが、実際に突合したら同一件で、しかも相手側の方が具体的だった)
- **次アクションを 1 行メモにする** — 「O2 に着手」だけでは復元セッションが動けない。素材の所在・見つからない場合の代替・参照すべき既存資料まで書く
- **ユーザーに貼らせる指示文を書く** — ユーザーの入力は `restore <path>` だけ。指示文ではなく**復元セッション向けの判断リスト**を書く
- **並行セッションとの優先規則を書かない** — 台帳を複数セッションが更新している状況で、本文と台帳が食い違ったときに復元セッションが止まる
- **パス・URL・番号を省略する** — 復元セッションは会話文脈を持たない。「あの記事」「例のリポ」は解決できない

## 保存テンプレート

save 時は以下をコピーして埋める。

```markdown
# Context Snapshot: <タスクの一言要約>
> 作成: YYYY-MM-DD / 目的: <clear/compact 後の再開>
> ⚠️ 本文は ground truth ではない。ブランチ/PR/commit/ファイルは git・gh で裏取りしてから信じること。

---

## 🚀 起動手順

このファイルを読んだら、**まず以下を順に実行**してから §未完ステップへ進む。**読み取り専用コマンドのみ**。

\`\`\`bash
# 1. リポの現在地を裏取り (git 文脈がある場合のみ。無いなら「git 復元は不要」と書いてこのブロックを削る)
cd <作業リポの絶対パス> && git fetch origin --quiet
git status -sb && git rev-parse --short origin/main   # 本文記録時: <SHA>
git worktree list

# 2. <ユーザー作業待ちの素材があれば、その到着確認コマンド。無ければ削る>

# 3. <並行セッションが同じ台帳を進めている場合、その状態確認コマンド。無ければ削る>
\`\`\`

**必読ファイル** (本 snapshot だけでは足りないもの):

| ファイル (絶対パス) | 何のために | 読む範囲 |
|---|---|---|
| `<絶対パス>` | <役割。本 snapshot との分担> | <節名 / 行範囲 / 抽出コマンド。全読みさせない> |

**時限**: <なし / 期日と対象。例: 2026-08-12 までに XX の資料を出す>

**このターンでユーザーに聞くこと**: <なし / 具体的に>

---

## 現在地
- <今どこまで来たか 1〜2 行。並行セッションの動きがあれば併記>

## ゴール
- <最終的に達成したいこと>

## ブランチ / PR / issue
- 作業リポ・worktree: `<絶対パス>` (git 作業がなければ「なし」+ 理由)
- ブランチ: `<branch>` (issue #<番号>)
- 記録時の origin/main SHA: `<短縮 SHA>`
- PR: <URL or 未作成>。merge 済みなら mergeCommit も

## ⭐ 直近の重要判断と理由 (最重要)
- <採用した方針と根拠 / 却下案とその理由>

## 未完ステップと次アクション

### 1. <次の一手の件名>

<着手時の判断分岐まで書く。「A を見て無ければ B」「前提が未了なら先にそれを促す」>

### 2. <以降同様>

## 落とし穴 / 触らないもの
- <踏むと事故る制約。1 行 × 最大 5 件。未追跡ファイルの所有者・別セッション必須の作業・先行する運用規範など>

## キーファイル
- `<絶対パス:行>` — <役割>

## 未解決の問い
- <ユーザー確認待ち・調査中の論点。努力目標 F を通した上で残るもののみ。他節で結論が出たものは書かない>

## ⭐ 復元セッションが自分で判断すること
1. <起動手順の実行と本文記録値との突合>
2. <着手対象の決定 (分岐条件を含める)>
3. <本文と現物が食い違う場合の優先規則>

判断に必要な値が本ファイルにも必読ファイルにも無ければユーザーに聞く (推測で埋めない)。
```

## 注意事項

- 本 skill は**手動 `/command` で自動発火機構を持たない**ため hook 実装は不要 (その旨を本文に明記することが skill 整合性の担保)。
- **save の合格条件は自己完結** — 項目が埋まっていることではなく、`restore <path>` だけで復元セッションが次の一手を打てること。save 完了前に「自己完結チェック」7 項目を通す。
- restore の起点はスナップショット本文でなく git/gh の実状態。本文は「次に何を確認するか」の索引として使う。
- 秘匿情報は書かず、パス参照に留める。
- 完全引き継ぎ (session 終了・別端末) は別の引き継ぎ生成手順に委譲する (棲み分け)。**ただし自己完結の要件はそちらにも同じ性質で存在する** (「次のセッションが読んだ瞬間に再開できる」という設計原則を持つのが通例)。両者を運用する場合は要件が食い違わないよう突合する。
