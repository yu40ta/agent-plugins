# Skill: Paper Search

自然文のトピックを受け取り、arXiv API を `ax` で叩いて技術論文を検索・取得し、関連度の高い上位 N 件を選別して日本語で要約するワンショット調査 skill。abstract + 書誌情報のみを扱い、PDF 全文取得はしない (v1 スコープ外)。

> **再現性の意味**: ここでの再現性は「同じ手順 (クエリ構築 → 取得 → 選別 → 要約) を毎回使える」ことを指し、「同一クエリで毎回同一の論文集合が選ばれる」ことは指さない。上位 N 件の選定は Claude の判断ベースで非決定的であり、同一クエリでも結果は変わりうる (機械的スコア式より判断品質を優先した意図的な設計)。

## 起動条件

- ユーザーが `/paper-search` を実行した場合
- 「論文を探して」「arXiv で調べて」「〜に関する研究/論文を調べて」等、技術論文の調査を求めた場合
- **自動発火はしない** (web 取得を伴うため手動起動とする)

## 検索ソースと API

- ソースは **arXiv のみ** (無料・無認証・レート制限は 3 秒/リクエストの公式制限のみ)。Semantic Scholar 等は 429 を踏むため v1 スコープ外
- ベース URL: `http://export.arxiv.org/api/query` (https へリダイレクトされる)
- 主要パラメータ: `search_query` / `start` / `max_results` / `sortBy` / `sortOrder`
- **レスポンスは Atom XML のみ** (JSON モードは無い)。`ax` の `--body` で生の XML を取得する
- 呼び出し例:
  `ax "http://export.arxiv.org/api/query?search_query=<query>&start=0&max_results=20&sortBy=relevance" --body`

## 処理フロー

### Phase 1: クエリ構築

1. ユーザーの日本語トピックを英語の arXiv クエリへ意訳する (`abs:"phrase" AND abs:keyword` 形式)。**日本語のまま検索しない** (arXiv ではほぼヒットしない)
2. トピックが曖昧で複数解釈されうる場合は「確認事項 N 点」の番号付きリストで地の文確認する (検索意図はユーザーしか判定できない事実のため AskUserQuestion ではなく地の文)
3. デフォルトソートは `sortBy=relevance`。ユーザーが「最新の」「直近の」等を明示した場合のみ `sortBy=submittedDate&sortOrder=descending` に切り替える

### Phase 2: 検索・取得

1. 1 回の呼び出しの `max_results` は既定 20。出力が harness の表示上限を超えると persisted-output ファイルへ自動退避される — **これは異常ではなく想定内の正常経路**であり、退避時はそのパスを Read して内容を確認する
2. **複数ページ取得時はページごとに個別の persisted-output ファイルへ退避されうる**。単一ファイルへの退避を前提にせず、各レスポンスの tool 結果に報告されるパスをその都度 Read する
3. **リクエスト間隔は 3 秒以上空ける** (arXiv 公式 ToU)。ページングで複数回呼ぶ場合も守る
4. 総取得件数の上限は既定 100 件 (5 ページ)。`opensearch:totalResults` がこれを超える場合、超過件数を明示して報告する (無言の切り捨てをしない)
5. **早期打ち切り**: `sortBy=relevance` で取得している場合、上位ページの時点で上位 N 件の質が十分と判断できれば、残りページの取得を打ち切ってよい (無条件に上限まで機械的に取得しない)
6. **同一論文の複数バージョン** (arXiv ID の `vN` 接尾辞違い) は名寄せし、最新版のみを候補とする
7. API エラー時: 429 (レート制限) だけでなく、過負荷時の **503 (Retry-After ヘッダ付き)** も同様に扱う。いずれも自動リトライせず、その場で中断してユーザーへ報告する

### Phase 3: 関連度選別

1. 取得した title/abstract を読み、テーマ適合度・実証の厳密さ・新規性の観点で上位 N 件 (既定 8 件) を選ぶ。**数値スコア式ではなく Claude の判断ベース** (機械的アルゴリズムと誤解されないため明記)
2. この選別段階では**トークン節約は働かない** (取得した abstract 全件を読む必要があるため)。節約が効くのは Phase 4 で深掘り対象を上位 N 件に絞る点のみ
3. 選外の論文はタイトル・出典のみの一覧に降格して提示する (完全に切り捨てない)
4. 選別の結果、関連論文が 0 件になった場合は「検索 0 件」と同様にキーワードを広げる案を提示する (取得はできたが選別で全落ちしたケースを API レベルの 0 件と混同しない)

### Phase 4: 要約提示

1. 上位 N 件は「論文名・**arXiv ID・abs URL**・出典・要旨」を構造化して要約する。識別子を明記することで、ファイル保存しない場合でもユーザーが後から再照会・検証できるようにする (ハルシネーション対策も兼ねる)
2. **venue/採録先は arXiv の comment フィールド等に明記がある場合のみ記載**し、無い場合は推測で補わない (arXiv は preprint 中心で採録先を保証しないため)
3. 複数論文を横断した傾向 (合意点・対立点) があれば、個別要約とは別に全体所感として添える
4. 要約は**常に日本語で出力する** (原論文・ヒット結果の言語を問わない)

## エラー処理

| 事象 | 対応 |
|---|---|
| 検索 0 件 (API レベル) | 構築した英語クエリ文字列をそのまま提示し (`このクエリで検索しましたが 0 件でした: <query>`)、キーワードを広げる案を提示する |
| 選別後 0 件 (取得はできたが関連論文なし) | 検索 0 件と同様にキーワードを広げる案を提示する |
| API エラー (429 レート制限・503 過負荷) | 中断してユーザーに報告する。**自動リトライはしない** |
| クエリの解釈が複数ありうる | 「確認事項 N 点」で地の文確認する |

## 出力先

- 既定は**チャット内のみ** (保存しない)
- ユーザーが「保存して」等**明示的に指示した場合のみ**、ユーザーが指定した保存先 (未指定なら `paper-search-<topic-slug>-YYYY-MM-DD.md` 等の分かりやすいファイル名) へ Markdown 保存する (opt-in)

## 注意事項

- 日本語トピック → 英語クエリへの意訳は必須手順 (英語のまま検索しないと arXiv ではほぼヒットしない)
- arXiv API はリクエスト間隔 3 秒以上を公式に要求する。連続ページングでも守ること
- レスポンスは Atom XML のみ (JSON は提供されない)
- 上位 N 件選別は Claude の判断ベースで非決定的 (同一クエリでも実行ごとに結果が変わりうる)。これは意図した設計
- persisted-output への退避は正常経路。複数ページ時は各レスポンスごとのパスを個別に Read する
- arXiv 以外のソース (Semantic Scholar・ACM・IEEE 等)・PDF 全文取得・フィールド投影抽出・定期実行は v1 スコープ外
