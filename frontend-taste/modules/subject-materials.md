# Subject Materials — 足し算層の収集の型

tells 回避 (引き算) だけでは「無臭で無個性」までしか行けない。taste の源泉は subject の実在物にある。**設計に着手する前に本 module の型で素材を収集し、収集できた実在物だけを設計に翻訳する**。無ければ捏造せず、無いなりの設計に落とす ([ai-slop-jp](../../ai-slop-jp/SKILL.md) の「実在しない情報を書かない」という鉄則と同構造)。

## 1. 収集の 7 カテゴリ

| カテゴリ | 集めるもの | 例 (飲食店なら) | 設計への翻訳 |
|---|---|---|---|
| 色 | subject の世界に実在する色 (材料・道具・空間・ロゴ) | 器の釉薬・暖簾・食材の色 | palette の base hex に昇格する (独立 hue はここからのみ足す) |
| 形 | 実在物の輪郭・比率・反復パターン | 皿の円・格子戸・箸の直線 | signature 要素・罫線/面分割のモチーフ |
| 質感 | 素材の手触り (紙・木・金属・布) | 和紙・木目カウンター | 背景処理 (グレイン/ノイズ)・罫線や面の質 |
| 写真 | 実写素材の有無・被写体・トーン | 料理写真・店内写真 | 有 = hero/figure の主役。無 = 写真ゼロ前提の figure 表現 + 実写真が入った時に化ける差し込み口 |
| 語彙 | subject 固有の言い回し・専門語 | 「お品書き」「大将」 | 見出し・ラベルの語の選択 (文言品質は文言専用の skill へ) |
| 数字 | 実在の数字 (年数・数量・時刻・価格) | 創業年・仕込み時間・席数 | 具体で語る構造要素。数字の見せ方 (級数ジャンプ・単位の扱い) に taste が出る |
| 固有名詞 | 人名・地名・銘柄・道具名 | 産地・器の窯元 | 信頼と個性の担保。輪郭のない一般語の置換候補 |

## 2. 収集手順

1. brief から subject を 1 つに固定する (曖昧なら先に pin する: 何の・誰向けの・ページの単一の仕事)
2. 7 カテゴリを上から埋める。**実在確認できたものだけ書く** — 出所はユーザーへの確認・実物・一次資料。「ありそうなもの」で埋めない
3. 空欄カテゴリは空欄のまま設計へ渡す (写真なし → 写真ゼロ前提の figure 表現へ・親 skill §4 / 色なし → 業種の実在物を調べるかユーザーに確認)
4. 収集結果をデザイントークン (palette 4〜6 hex・type 役割・signature 候補) に翻訳し、各トークンに「どの実在物由来か」を 1 行添える (由来を書けないトークンは default の疑い)

## 3. 二層 taste への割り当て (親 skill §4 と対)

- **template-level**: 業種の world に共通する実在物 (業種を代表する形・質感・レイアウト慣習) → 骨格・レイアウト構造の signature に使う。テンプレ設計単位で宣言する
- **deliverable-level**: 案件固有の実在物 (その店の色・数字・固有名詞・写真) → 差し込みで個性を立てる。**色と語の差し替えだけ (recolor) は deliverable-level taste を満たさない** — 少なくとも 1 つ、案件固有の実在物が視覚要素 (figure・signature の変奏・数字の見せ方) に翻訳されていること

## 注意事項

- 実在物の捏造禁止: 「創業 50 年」等の数字・固有名詞を素材が無いのに置かない (placeholder は `{{...}}` で明示し、実データ差し込み前提であることを成果物に残す)
- 収集はユーザーへの確認 1 往復で済む粒度に絞る (7 カテゴリ全部の完璧な回答を要求しない。優先は色・写真・数字の 3 つ)
- 収集した素材が tells と一致する場合 (例: subject の実在色がたまたま terracotta) は、Pre-Flight 手順 4 の宣言 (subject 由来の理由 + 代替 1 案比較) を書けば採用できる — 実在物由来こそが宣言の根拠になる
