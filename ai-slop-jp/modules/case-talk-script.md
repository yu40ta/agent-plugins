# Case: 発声台本 (登壇・プレゼン・研修のトークスクリプト)

読むための文章ではなく、**人が声に出して読み上げるための文章**。書き言葉・SNS の癖 (体言止めの省略・修辞疑問・倒置・決め台詞) を持ち込むと、発声した瞬間に不自然になる。「目で読んで自然」と「口で言って自然」は別物で、後者を最優先する。

## 目的関数

登壇者が目で追いやすく、口に出して淀まず、聴き手の耳にまっすぐ届く。1 行が読み上げの 1 呼吸。

## 適用

- 人間らしさ: H5 特定の読み手 ◎ (聴衆)・H6 声の癖 ○・H7 省略と余白 ○・H3 温度 △。H1 立場は台本の目的次第 (啓発・報告なら △)
- 採点: 具体性・削減・リズムの 3 軸を主に見る (リズム = 音読して淀まないか、が最重要)。合計は 3 軸で 21/30 未満なら書き直し
- 書き手の声: 本人名義の登壇なら (用意していれば) 自分の声のプロファイルの register を参照するが、**発声台本は「話し言葉」扱い**。声のプロファイル側にある「話し言葉の癖は書き言葉に持ち込まない」という規律は**書き言葉側の制約**であり、発声台本には逆に適用しない (下記「話し言葉の優先」)。
- 併用: 台本を対話で 1 枚ずつ作るワークフローを別途持っている場合は、そちらで台本を組み立てる。本 module は台本本文の AI 臭・口語適性の SSOT を担う。

## 話し言葉の優先 (この文書種の核)

- **発声される台本は話し言葉である**。自分の声のプロファイルが「本人名義の書き言葉では観測ゼロ」とする関西弁・崩した口語も、発声台本では書き言葉規律の対象外として扱う (矛盾しない。プロファイル側の禁止は書き言葉側の話)。
- ただし **AI からは能動的に方言・崩しを入れない**。ユーザーが具体的に指定した表現 (「言われへんやん」等) はそのまま採用し、Claude 側で標準語に直さない (コア §6 鉄則 5・物真似臭の回避)。
- **非指定の方言箇所の既定は標準語化**。下書きにユーザー既記の方言があっても、指定 (「ここは残して」等) が無ければ標準的な話し言葉に均す。保持したい方言は全て明示指定してもらう運用にする (指定漏れを AI が忖度して残すと、どこまで残すかの基準がぶれる)。迷う箇所は標準語化したうえで「ここは方言のまま残すか」を確認する。
- 迷ったら「実際に登壇者がその場で口に出して言うか」を基準にする。SNS の一撃・書き言葉の整った構文に寄せない。

## 種別固有 deny (機械ゲートへの追加)

コア §4 の #2 (締めの悟り構文)・#4 (丸投げ疑問)・#16 (文末単調) はこの文書種で特に頻出する。加えて smell-catalog の **C8 結論の引っ張り (まどろっこしさ)**・**C3 列挙導入の体言止め宙吊り (口頭文限定)** も発声台本で顕著に出るが、これらは汎用症状として smell-catalog に定義済みなので本 module では重複記載しない — 判定質問・処置は smell-catalog を参照する。以下は発声台本の種別固有 deny:

| 症状 | 検知 | 処置 |
|---|---|---|
| 体言止めの省略 (書き言葉臭) | 「代表は〜」「ポイントは〜」等、口頭なら述語を補うべき箇所の名詞止め | 話す言い回しに (「代表的なのは〜ですね」「ポイントは〜という点です」)。体言止め自体はリズムづけに使ってよいが、説明の主文を名詞で切り上げない |
| 答えを待たない修辞疑問 | 「〜、聞いたことありますか。」の直後に自分で説明を続ける | 聞き手の無知を先に肯定してから提示 (「あまり聞き馴染みがないかも知れませんが〜という言葉があります」)。実例は下の較正実例 §実例 2。①「馴染みがない=知らなくて当然」を先に置き心理を先回り ②「〜という言葉があります」は存在提示だけで答えを要求する圧がない |
| 倒置・後出し否定 | 「ここがポイントで、〜はないんです」型の回りくどい語順 | 主語 → 結論を直結 (「〜がないことがポイントです」) |
| 気の利いた締めの一言 | 段落末の「〜とも言えるんです」「〜が大事なんです」の付け足し | 直前の文で既に立っていれば削除 (§4 #2)。無くても意味が通るなら足さない |
| 硬い商売語・漢語・比喩の口頭混入 (硬すぎ) | 「目減り」「知識を配る」「散逸」「属人化」等、口に出すと商売っぽい/漢語臭い/比喩的な語 | 平易な口語に (「実力を発揮できなくなる」「知識を伝える」「散らかってる」「人に依存してる」)。ただしフォーマル題材では「体系化」「可視化」「定量的」等、口頭でも通じる硬い語は許容する |
| 過剰な口語化 (逆流・軽すぎ) | 平易化・声の自然さを意識するあまり内容に不釣り合いに崩す (「〜とは何か」→「〜って何か」)。フォーマル題材 (コンプライアンス・規程・制度説明) で語彙の格が下がる | 崩しは「まどろっこしさを削る」方向であって「軽くする」方向ではない。フォーマル題材では格に合う語彙を保つ (「って何か」→「とは何か」、砕けた「コツ」より「ポイント」)。上の行 (硬すぎ) と混同しない — あちらは硬すぎ、こちらは軽すぎで、題材の格に合わせるのが軸 |

## 較正実例 (2026-07-22 ハラスメント勉強会・課長→課員の発声台本)

いずれも「目で読めば通るが、口に出すと不自然」を直した実例。トーンはビジネスカジュアル。

### 実例 1: 体言止めの省略を話し言葉に

**before**: 「代表はセクハラとパワハラ。」
**after**: 「代表的なのはセクハラとパワハラですね。」
直した点: 名詞で切り上げる書き言葉臭を、述語を補った話し言葉に。「〜ですね」で聴き手に向く。

### 実例 2: 答えを待たない修辞疑問

**before**: 「『インシビリティ』という言葉、聞いたことありますか。無礼とか、礼を欠いた振る舞い、という意味です。」
**after**: 「あまり聞き馴染みがないかも知れませんが、『インシビリティ』という言葉があります。無礼とか、礼を欠いた振る舞い、という意味です。」
直した点: 答えを待たず説明に入る修辞疑問は白々しい。①聞き手の無知を先に肯定して心理を先回り ②「〜という言葉があります」は存在提示だけで答えを要求する圧がない。

### 実例 3: 倒置・後出し否定を直結に

**before**: 「ここがポイントで、明確な攻撃性はないんです。」
**after**: 「明確な攻撃性がないことがポイントです。」
直した点: 「ポイントで〜ないんです」の回りくどい後出しをやめ、主語→結論を一息で。

### 実例 4: 冗長をシンプル・直感へ

**before**: 「その分、チーム全体が本来出せる力より下がってしまう。」
**after**: 「チーム本来の実力を発揮できなくなってしまう。」
直した点: 比較節を畳んで一息で言い切れる長さに。口頭は「シンプルかつ直感的に伝わる」を基準にする。

### 実例 5: ユーザー指定の口語 (方言) はそのまま採用

**採用**: 「『じゃあ何も言われへんやん』と思うかもしれません。」
判断: 発声台本 = 話し言葉なので声のプロファイル側の関西弁禁止 (書き言葉規律) の対象外。ユーザー指定表現をそのまま活かし、標準語に直さない。AI から能動的には方言を入れない。

## 連作 (1 枚ずつ作る台本) の注意

同じ登壇の隣のスライドと、文体・敬体・崩しの度合いを実測して揃える (コア §6 鉄則 4)。1 枚だけトーンが浮かないようにする。ワーク・質疑の「間」の指示は台本本文と区別して書く (読み上げないため)。
