# AI 臭 症状カタログ (SSOT)

ai-slop-jp コア §4 (機械ゲート) は本カタログの最頻 20 の抜粋であり、本ファイルが全量の SSOT。長文論証向けの専用文章規範側にある対応表は、長文論証で特に出る型に絞ったサブセットになる想定。

検知は 2 形式に統一してある。**主観の入る「なんとなく AI 臭い」を検知基準にしない**:

- **文字列**: そのまま照合できる (判断ゼロ)
- **判定質問**: yes/no で答えられる問い。yes ならヒット

## C1 最頻値への回帰

| 症状 | 検知 | 処置 |
|---|---|---|
| 輪郭のない一般語 | 文字列: 効率化・最適化・活用・向上・課題・推進・実現・強化・促進 | その場の具体に置換 (「毎朝 30 分の集計が 3 分」) |
| 空虚な強調 | 文字列: 非常に・極めて・圧倒的に・革命的・劇的に・徹底的に | 数と事実で語る。強調語は削除 |
| バズワード | 文字列: シナジー・パラダイムシフト・ゲームチェンジャー・ソリューション | 自分の言葉で言い換え。できなければ削除 |
| 紋切り型の比喩 | 判定質問「この比喩は他の記事でも見た形か」(「〜の海」「羅針盤」「両輪」「架け橋」) | 比喩を捨てて平易な動詞で言う |
| 慣用句のひねり | 判定質問「指す内容が一意に決まるか」→ 決まらなければヒット | そのまま言う |
| 自家製漢語ジャーゴン (Claude 応答) | 判定質問「その二字熟語はユーザーか公式文書が使った語か」→ no ならヒット (実例: 退避・従属・純化・再裁定・確立フロー) | 日常語に言い換える (退避→書き残す/保存する、再裁定→見直す) |
| 動詞句の複合名詞化 (Claude 応答) | 判定質問「動詞句・修飾句を自家製の漢語複合名詞に圧縮していないか」(実例: 採用指摘・横断参照)。定着した操作名 (一括置換等) は除く | 動詞を残して書く (採用指摘→採用した指摘、横断参照→ファイルをまたぐ参照) |
| 名詞圧縮スタックの参照 (Claude 応答) | 判定質問「対象を『#4 (X + Y のリライト)』のような内部番号 + 括弧内名詞列で指していないか」 | 短い文で対象を具体に名指す |
| 英語断片の混成名付け (Claude 応答) | 判定質問「日本語 + 英語断片を混成した自家製の名付けをしていないか」(実例: 「校正 core」型) | 日本語で統一して名付ける ([LABEL] 体系とは別物として扱う) |
| 格上げ動詞ぼかし (報告書/Claude 応答) | 文字列: 進化させる・深化させる・加速させる・高度化する (中身のない格上げ動詞で実態をぼかす) | 何をする施策かの具体動作に置換 (例: 進化させる→チェックリストを配布し棚卸しを義務化する) |
| 戦争メタファー・勇ましい比喩 (レビュー/報告書) | 文字列: 主戦場・射線・地平・攻めどころ・要塞・防衛線 (実態を戦争比喩で置換する自家製ジャーゴン) | 実態を平易な語に置換 (主戦場→主に扱う領域、射線→連絡ルート) |
| 情感の漢語圧縮 (Claude 応答/レビュー) | 判定質問「感覚・状態を『〜感』の自家製名詞に圧縮していないか」(実例: 到達感・浸透感・定着感・肌感)。定着した既存語 (安心感・違和感等) は除く | 感覚を素直な動詞で書く (到達感が薄い→充分に到達できていない、浸透感→現場に伝わっていない) |
| 中身のない副詞 (Claude 応答/レビュー) | 文字列: 確定的に・実質的に・本質的に・構造的に (副詞で結論を強調するが実態を伴わない) | 副詞を削除し、代わりに具体条件を書く (「確定的に進む」→「〜という条件で進む」) |

## C2 全方位への配慮 (立場の不在)

| 症状 | 検知 | 処置 |
|---|---|---|
| 両論併記逃げ | 判定質問「この文の結論を一行で言えるか」→ 言えなければヒット。「良い面も課題も」「一長一短」 | 立場を選んで言い切る |
| 留保逃げ | 文字列: 「〜とは限りません」「〜という側面もあります」「〜な場合もあります」 | 根拠があれば断定へ。**反例が実在する主張のみ留保を残す** (下記「誤検知の境界」) |
| 丸投げ疑問 | 文字列: 「〜ではないでしょうか」「あなたはどうですか?」「いかがでしたか」 | 断定に直すか削除 |
| 一般論着地 | 文字列: 「人それぞれ」「バランスが大事」「ケースバイケース」「正解はありません」で締める | 自分のケースの答えを書く |
| 責任回避の受動・伝聞 | 判定質問「『〜と思われる』『〜とされている』を、主語を立てて言い直せるか」→ 言い直せるならヒット | 主語を立てて言い切るか、出典を書く |
| 全方位の敬意 | 文字列: 「皆様それぞれの〜」「一人ひとりに合った〜」(具体なし) | 特定の読み手一人に向けて書き直す |
| 循環参照ヘッジ | 判定質問「断定した直後に同語反復のヘッジ (『〜済み (〜済みであることが前提)』型) を重ねて自己否定していないか」 | 前提の真偽が不明なら「要確認」と明示し、確認済みなら断定のみ残す |

**判断が要る C2 症状 (deny 化しない・§5 採点で判定)**: 留保逃げの技術記事版 — 考慮事項を疑問形で並べるだけで終わっていないか (挙げたら扱い方針まで書く。判定は `case-article.md` 較正実例参照)。

## C3 均質な情報密度 (リズムの死)

| 症状 | 検知 | 処置 |
|---|---|---|
| 文末単調 | 文字列: です/ます/ました のいずれかが 3 文以上連続 | 体言止め・言い切り・短文をぶつける |
| 文長均一 | 判定質問「連続 4 文の長さがどれも 40〜60 字に収まっているか」 | 10 字の文を 1 本入れる。または 2 文を接続して緩急を作る |
| 接続詞連打 | 文字列: また・さらに・そして・加えて が段落内で規則的に反復 | 削る。並列が本当に必要なら一文にまとめる |
| 体言止め乱用 | 文字列: 体言止めが 3 文以上連続 (直しすぎの新 AI 臭) | 体言止めは効かせ所 1〜2 箇所に絞る |
| 列挙導入の体言止め宙吊り (口頭文限定) | 判定質問「音読される文 (登壇台本・口頭原稿) で、これから列挙する予告を体言止めで止めていないか」(実例: 「お願いしたいことを 3 つ。」の後に項目が続く) → yes ならヒット。**文中の言い切りの体言止め (「〜できる制度です。」) は対象外** | 動詞で受けて閉じる (「〜を 3 つ伝えます」「〜が 3 つあります」)。台本の口頭最適化は発声台本向けの case module (case-talk-script.md) を参照 |
| 読点の等間隔 | 判定質問「どの文も読点が 2 個ずつ入っているか」 | 読点ゼロの短文を混ぜる |

## C4 読者の不特定

| 症状 | 検知 | 処置 |
|---|---|---|
| 全方位文 | 判定質問「この文を読んで顔が浮かぶ読み手を一人言えるか」→ 言えなければヒット | 読み手を一人決めて書き直す |
| 属性の羅列 | 文字列: 「エンジニアの方も、そうでない方も」「初心者から上級者まで」 | 主読者一人に絞る。他は捨てる |
| 権威性の並列 | 文字列: 「元 A・現 B」のような肩書の重ね掛け | 文脈で最も刺さる一本に絞る |

## C5 体験の不在

| 症状 | 検知 | 処置 |
|---|---|---|
| テンプレ感想 | 文字列: 「刺激的でした」「学びの多い時間」「〜に感謝です」「勉強になりました」 | 具体の事実 + 温度に置換。素材がなければ書き手に問う |
| 成果の抽象化 | 文字列: 「多くの学びを得た」「大変有意義だった」「見識が広がった」 | 学びの中身を 1 個だけ具体に書く |
| 捏造風の例え話 | 文字列: 「例えばあなたが〜だとしましょう」「あるエンジニアの話です」(実在不明) | 実例に置換するか削除。**体験の創作は禁止** (コア §6 鉄則 1) |
| 教科書の言い換え | 判定質問「この段落は公式ドキュメントの要約と区別がつくか」 | 自分の環境で起きたこと・数字を足す。なければ要約と明示する |

## C6 「ちゃんと書いてる感」の演出

| 症状 | 検知 | 処置 |
|---|---|---|
| 対句の決め台詞 | 文字列: 「〜ではなく、〜」「X は〜。でも本当は〜」「〜。そう、〜なのです」が 1 文書 2 回以上 | 1 回まで。残りは平叙文に |
| 締めの悟り構文 | 文字列: 末尾の「大事なのは〜」「〜していきたいと思います」「〜かもしれません。」「そんな風に思います」 | 削除するか、立場の言い切りに置換 |
| 予告と総括 | 文字列: 「今日は〜についてお話しします」「まとめると」「いかがでしたか」 | 本題から入る。まとめずに終わる |
| カウント癖 | 文字列: 「重要なポイントは 3 つあります」「理由は 3 つ」 | 数の宣言を消して中身から入る (本当に列挙が要る手順書は可) |
| 行頭絵文字列 | 文字列: ✅🔥✨💡🚀 等の行頭連続 | ゼロにするか、効く 1 個 |
| 「!」連発 | 文字列: 1 文書に 3 回以上 | 1 回まで (voice profile が明示的に許す場合を除く) |
| 箇条書き逃げ | 判定質問「この箇条書きを地の文 2〜3 文で言えるか」→ 言えるならヒット | 地の文に戻す (手順・一覧データは箇条書きが正当) |
| 飾り記号 | 文字列: 【重要】・★・◆・■・意味のない「——」 | 削除。中身で引く。強調が要るなら 1 文書 1 箇所まで |
| 常識引用の引き延ばし | 文字列: 「〜という思い込みを持つ人も少なくありませんが」 | 「『〇〇』は違う」レベルまで圧縮 |
| 見出しの総花化 | 文字列: 「〜について」「〜のポイント」「〜まとめ」 | その節が答える問いか対象を指す具体句に |
| 発見の自己劇化 (Claude 応答) | 文字列: 「重要な発見です」「決定的な発見」「核心が見えてきました」「方針がシャープに」+ 数の宣言 (「重要な発見が 2 つ」) | 数の宣言をやめ、発見の中身から入る |
| 謝罪・誠実さの口上 (Claude 応答) | 文字列: 「その通り。申し訳ない。」「正直に選ぶと」 | 削除。結果・原因・次の行動の事実だけで応える |
| 場面転換ナレーション (Claude 応答) | 文字列: 「決定が揃ったので」「決定が出揃ったので」 | 前置きを削り、行動をそのまま書く |
| プロセスの俗語擬人化・医療メタファー (Claude 応答) | 文字列: 死ぬ・飛ぶ・事故る (俗語擬人化) / 止血 (医療メタファー) / 3 兄弟 等の擬人化ネーミング | 何をするかで言う (失敗する・スキップされる・最優先の 1 点に絞る) |
| メタ自己言及ラベル (Claude 応答) | 判定質問「見出し・ラベルが書き手の行為の説明句になっていないか」(実例: 「書き残した判断」「最重要の退避内容」) | 対象そのものを指す体言に置換する (「記録内容」「ステータス」) |
| 重要度アナウンスのメタラベル | 判定質問「複数の異なるセクションに"ここが要点"を意味する同義語ラベル (本筋=・核心:・肝= 等) が付き、かつ中身 (対比構文等) はラベルを外しても単独で意味が通るか」→ yes ならヒット。既存の「メタ自己言及ラベル」(書き手の行為の説明句) とは別物 — こちらは行為でなく重要度そのものの宣言を同義語ローテーションで振る点が異なる (grep 検知を逃れやすい亜種) | ラベルを外し中身だけを残す。話者が本当に強調したい箇所が 1 つだけならそこにのみ残してよい |
| 稟議の願望止め (報告書) | 文字列: 「〜を図りたい」「〜を推進したい」 | 動作で言い切る (例: 個別申請を包括承認に切り替える) |
| 記号 ID による見せかけの体系化 (仕様書) | 文字列: KR#・F#・A# 等の記号+ハッシュ+番号 ID | 削除。ID なしの平文で指す (`case-spec-doc.md` 較正実例参照) |
| 演出的鉤括弧強調 | 判定質問「自前の概念語・見出し的な断定を鉤括弧で強調し、直後に定義・elaboration が続かないか」→ yes ならヒット (実例: 「AI ネイティブな開発プロセス」「仕組み化」)。**誤検知の境界**: 単発使用かつ直後に定義展開が続く用語紹介 (共有語彙の初出展開) は対象外 | 鉤括弧を外し地の文に馴染ませる。反復する場合は 1 箇所のみ残す |
| 見出し末尾のテーマ絵文字 | 判定質問「リスト項目・見出しの語尾に、内容に合わせて選んだ単発絵文字が 3 件以上一律に並んでいないか」(行頭絵文字列とは別種・単発かつ末尾) | 全廃するか、効く 1 個のみ残す |
| タグライン見出しの反復 | 判定質問「見出し・章題・項目名・タブ名に『A が、B。』『A を、B する。』のように助詞 (は/を/が/で/も) の直後に読点を挟んで言い切る文型 (動詞で終わる型・体言止めで終わる型のどちらも該当) が同一文書の見出し群 (階層をまたいで通算) で 2 件以上使われていないか」→ yes ならヒット。誤検知の境界: キービジュアル・扉・締めの 1 箇所のみの使用は効かせ所として正当なので対象外。読点が誤読防止に必要な場合 (係り先が曖昧・修飾が長い) も対象外。既存の「見出しの総花化」(情報量ゼロの定型句)・「読点の等間隔」(本文のリズム)・「メタ自己言及ラベル」(書き手の行為の説明句) とは別物なので二重計上しない | 体言止めの短句に圧縮する (「一人で、班を動かす。」→「最小単位の班運営」 / 「チームの型を、層として積む。」→「チームのレイヤー化」 / 「課題は、意思決定の遅れ。」→「意思決定の遅延と改善策」 / 「施工範囲の差が、速度の差になる。」→「施工範囲ごとの進捗管理」)。長文向けの文章規範にある見出しの禁止事項と重なるが、本症状は文型 (助詞 + 読点) の反復を判定する点が異なる |

**判断が要る C6 症状 (deny 化しない・§5 採点で判定)**: フレームワーク過大 — 案件規模に対し PMF/PRD 系フレームワークを総動員していないか (判定は `case-spec-doc.md` 較正実例参照・provisional)。温度の階調 — chat/sns の絵文字・「!」の許容度は用件の性質 (事務周知か盛り上げ告知か) で変わる (判定は `case-chat.md`/`case-sns.md` の誤検知の境界参照・provisional)。

## C7 書き言葉バイアス

| 症状 | 検知 | 処置 |
|---|---|---|
| ビジネス名詞の混入 (SNS/チャット) | 文字列: 接触・実施・取り組む・活用する・連絡が来る・共有させていただきます | 口語動詞に: 使う・やる・送る・動く・もらう |
| 過剰敬語・クッション連打 | 文字列: 「お忙しいところ恐れ入りますが」「ご多忙のところ恐縮ですが」「〜いただければと存じます」が 2 回以上 | クッションは 1 回まで。用件を先に |
| 「させていただく」多用 | 文字列: 1 文書に 3 回以上 | 「します」「やります」に戻す |
| AI 定型応答 | 文字列: 「承知いたしました。それでは以下に〜」「以上となります」 | 人が打つ返事に: 「了解です」「見ておきます」 |
| 口語副詞の後付け | 文字列: 非口語文への「ぶっちゃけ」「めちゃ」「正直」添加 | 削除。口語化は語彙でなく構文から (短文化・言い切り) |
| 使役ぼかし・方向ぼかし (Claude 応答) | 判定質問「使役表現や方向語で結果を婉曲にしていないか」(実例: 「参照を誤らせる」→壊れる、「悪化させる方向」) | 何がどうなるかを直接書く |
| 二人称「あなた」(Claude 応答) | 文字列: 「あなた」 | 対象を明示するか二人称を省く |
| 形容詞ぼかし (報告書/Claude 応答) | 文字列: 甘め・厳しめ・〜めに (操作の実態を形容詞でぼかす) | 実態を動詞で直接書く (甘め→水増しする) |
| 平仮名口語末尾 (全文書種) | 文字列: 「〜ぎみ」(重複ぎみ・遅れぎみ)。書き言葉に平仮名の口語的接尾を付ける表記。同系の「〜め」(甘め・多め・早めに) は上の「形容詞ぼかし」で扱い二重計上しない | 正規表記か言い切りに (「重複ぎみ」→「重複気味」または「重複している」)。報告書・運用文書・レビューコメントでは特に避ける |
| 字形近似の誤変換 (Claude 応答/成果物全般) | 文字列: 常用漢字外の低頻度字が字形近似字に取り違えられて混入 (実例: 「辻褄」→「辻褒」/「箇所」→「箱所」/「範」→「篇」で誤出力)。JSON エスケープ経由の投稿では特に発生しやすい | 該当語をリテラル生成しない運用に切り替え、平易語に置換 (辻褄・整合性→「整合」「食い違い」/ 箇所→「部分」「対象」)。取り違えられた 3 語 (褄・箇・範) と 3 誤字 (褒・箱・篇) は特に警戒する (JSON エスケープ + 常用漢字外の低頻度字が字形近似字に化けやすい。長時間のレビュー投稿作業で連続発生した実績がある) |
| **非日本語文字の混入 (全文書種・Claude 生成物全般)** | 文字クラスで機械判定する。日本語の地の文に**キリル文字** (`[А-Яа-яЁё]`・例「初稿から этот 分量で」) ・**ハングル** (`[가-힣]`) ・**日本語で使わない簡体字/繁体字** (为・关・东・齐・说・这 等) が混入する。上の「字形近似の誤変換」は日本語漢字同士の取り違えで別項目 (二重計上しない) | 該当箇所を日本語に直す。**混入は単発のタイプミスではなく生成側の劣化シグナルなので、直したうえで長時間作業の前にコンテキストをクリアすることを検討する** (長尺セッションの終盤で助詞・連体詞の位置にキリル文字が混入した実績がある) |

**非日本語文字の一括検知** (提示前・commit 前の機械チェック)。**許可リスト方式で書く** — 簡体字を列挙する禁止リスト方式は列挙外の字が素通りする (頻出 8 字を列挙したパターンで「网络的组织」が 0 件になった実測がある):

```bash
python3 -c "
import re, sys
allowed = re.compile(r'[ -~\s　-〿぀-ゟ゠-ヿ一-鿿＀-￯①-⓿─-➿㈀-㏿℀-⅏Ⅰ-ↂ←-⇿‐-⁞†-‡•§¶°±×÷≠≤≥∼]|[\U0001F000-\U0001FAFF]')
for n, line in enumerate(open(sys.argv[1], encoding='utf-8'), 1):
    bad = [c for c in line if not allowed.match(c)]
    if bad: print(f'{n}: {\"\".join(dict.fromkeys(bad))}  |  {line.rstrip()}')
" <file>   # 無出力が正常
```

許可範囲は**日本語文書で正当に使う文字を実測で洗い出して確定した**。ローマ数字 (Ⅲ)・丸数字 (①)・単位記号 (㎡ ℃ ㈱)・罫線 (─ │)・矢印 (→ ⇒)・節記号 (§)・数学記号 (± × ≠)・emdash・絵文字を含む。**較正を省いて「日本語 + ASCII のみ許可」で書くとこれら全部が誤検知になる** — 初版がそれで、本カタログ自身に掛けたら 30 行超が誤検知になった (`→` と `§` が主因)。許可範囲を変えたら本カタログと `ai-slop-jp.md` を対象に掛けて 0 件を確認すること。

- **簡体字の一部は CJK 統合漢字なので上記でも検知できない** (为・这 等は日本語漢字と同じブロックにいる)。この層は文字クラスでは判定不能なので、文脈で読んで気付くしかない
- キリル文字・ハングル・タイ文字はこの方式で確実に拾える
- **例外**: 外国語の固有名詞・引用・多言語を正当に扱う文書、および本カタログのように**非日本語文字を例示する文書**では検知が出て当然。ヒット = 即処置ではなく、該当行が意図的かを確認して終わる (機械ゲートの他項目と性質が違う)
- 検知できたら**その文字を直すだけで終わらせない** — 生成側の劣化シグナルとして扱う

## 処置後の再照合

置換で別の症状を作っていないかを 1 周だけ確認する:

- 断定化しすぎ → 根拠のない断言の連発は「温度のない命令臭」になる。断定は根拠を持つ主張にだけ使う
- 口語化しすぎ → 報告書・運用文書に口語動詞を持ち込むのは逆方向の誤適用 (§3 マトリクスに従う)
- 削りすぎ → 用件・期限・宛先など読み手が動くのに必要な情報を削っていないか

## 誤検知の境界 (ヒットでも処置しないケース)

- **留保が正当**: 反例が実在する主張 (「必ず動くとは限らない」が事実) は留保を保持する。不確実性の表明は誠実さであって逃げではない — 逃げかどうかは「根拠を書けるのに書いていないか」で判定する
- **箇条書きが正当**: 手順・チェックリスト・一覧データ。地の文に戻すと読み手が作業しにくくなるもの
- **絵文字が正当**: Slack のリアクション文化圏の 1 個 (:raised_hands: 等)、voice profile が register で許可したもの
- **「!」が正当**: voice profile が頻度上限つきで許可した register (本人の実績がある場合のみ)
- **定型が正当**: 法務・規程・障害報告など、定型であること自体が読み手の安心材料になる文書
